# 실시간 점수 반영 개선 · 프론트 전달 사항

## 원인과 이번 변경

기존 운영 크롤러는 경기 중 스코어보드를 2분마다 읽고, 지연·중단 상태에서는 5분마다 읽었다. 이 시간에 KBO 자체 업데이트 지연, 서버 수신 처리, 프론트 재조회 시간이 더해진다. CPU 증설보다 수집 주기를 줄이는 것이 효과적이다.

| 상태 | 새 수집 주기 |
| --- | --- |
| 하나라도 LIVE | 15초 |
| 경기 시작 대기·상태 미확인 | 30초 |
| 남은 모든 경기가 DELAYED/SUSPENDED | 60초 |
| 모든 경기 종료 | 기존 종료 후 5·15·30분 확인 후 종료 |
| 경기 없는 날 | 계획 확인만 수행, 경기 수집 태스크 미실행 |

이 주기는 응답 처리가 끝난 뒤 다음 요청까지의 간격이다. 원본 갱신 지연과 네트워크·서버 처리 시간이 더해지므로 경기장에서 발생한 득점을 15초 이내 반드시 반영한다는 보장은 아니다. LIVE 첫 인식은 30초 대기 주기의 영향을 받는다.

스코어보드 한 번의 요청으로 당일 전 경기를 읽는다. 진행 경기와 중단 경기가 함께 있을 때 진행 경기를 우선한다. Fargate CPU/메모리와 실행 시간은 기존 구성을 사용한다. LIVE 스코어보드 요청은 시간당 약 30회에서 최대 약 240회로 늘어난다. DynamoDB 등 관측·요청 제한 처리도 늘어나지만, 같은 점수·상태를 SQS로 중복 발행하지 않는 기존 처리는 유지한다.

시간당 정상 요청 한도 300회, 재시도 포함 360회로 설정한다. 빠른 주기에 비해 한도가 부족하면 시작 전 설정 검증에서 실패한다. 429/403·차단 응답 시 중단 및 재시도 제한은 그대로 적용한다.

## 프론트 연결 요청

1. LIVE 경기의 점수·이닝을 표시하는 화면이 보이는 동안 게임/타임라인 API를 10~15초마다 재조회해 주세요. 서버에서 빠르게 갱신해도 화면이 재조회하지 않으면 점수는 그대로 보입니다.
2. 화면 복귀 시 즉시 재조회하고, 탭 숨김·화면 이탈·경기 종료 시 주기 조회를 멈추거나 느리게 전환해 주세요. 이전 요청이 끝나기 전에 새 요청을 겹쳐 보내지 않도록 해 주세요.
3. 점수의 `resultObservedAt`은 서버 관측 시각입니다. 실제 득점 시각으로 표시하지 말아 주세요.
4. 기록 저장 후에는 생성 응답의 점수로 카드를 갱신해 주세요. 촬영 전에 화면에 있던 점수를 그대로 확정 표시하지 말아 주세요.
5. 기록의 `homeScore`, `awayScore`, `scoreObservedAt`은 관측 이력이 없으면 null일 수 있습니다. 이 경우 0:0으로 확정 표시하지 말고 미확인 상태로 표시해 주세요.

## 역전 직후 기록과 후보정의 한계

현재 기록 저장은 `recordedAt` 이전에 관측한 가장 최근 점수를 저장한다. `scoreObservedAt`은 그 점수를 마지막으로 관측한 시각이다. 저장된 점수는 이후 경기 점수와 별개로 보관된다.

예를 들어 18:30:00에 2:3을 관측하고 18:30:15에 4:3을 관측했다면, 득점이 그 사이 정확히 언제 발생했는지는 현재 소스로 알 수 없다. 18:30:08에 촬영한 기록을 무조건 4:3으로 바꾸면 실제 득점 전 촬영을 역전 후로 잘못 보정할 수도 있다. 15초 수집은 이 불확실한 구간을 줄인다.

정확한 자동 후보정에는 실제 득점 발생 시각을 가진 플레이 단위 데이터가 필요하다. 사용자 직접 정정 기능은 별도 방식으로 구현할 수 있지만, 자동 관측값과 사용자 정정값을 구분하고 수정 이력을 남겨야 한다. 이번 변경은 수집 지연을 줄이는 것으로, 기존 기록의 점수를 추정해 덮어쓰지는 않는다.

## 검증

- 크롤러 전체 테스트 134개 통과.
- 시작 대기 → LIVE → 중단 → 재개 → 종료 전환의 실제 실행 루프 간격 검증.
- LIVE/중단 혼재 시 LIVE 우선, 경기 없는 날 종료, 기존 종료 재확인, 요청량 부족 설정 거부 검증.
- 운영 적용 및 실제 수집 결과는 PR에 기록한다. 경기 중 체감 지연은 다음 실제 경기에서 KBO 원본·서버·프론트 시각을 함께 비교해야 한다.
